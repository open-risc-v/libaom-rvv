# libaom G3：RVV 卷积/CDEF 内核功能验收（2026-11-14）

上游 `av1/common/riscv/` 共 11 个 RVV 源文件 + `aom_ports/riscv_cpudetect.c` 运行时派发：

```
convolve_rvv.c  highbd_convolve_rvv.c
compound_convolve_rvv.c  highbd_compound_convolve_rvv.c
wiener_convolve_rvv.c    highbd_wiener_convolve_rvv.c
cdef_block_rvv.c
```

| 侧 | 配置 |
|---|---|
| A | `AOM_TARGET_CPU=riscv` + `ENABLE_RVV=ON`，`-march=rv64gcv` |
| B | `AOM_TARGET_CPU=riscv` + `ENABLE_RVV=OFF`（RTCD 派发 `--disable-rvv`），同 march |

| 项 | A | B |
|---|---|---|
| 5 帧编码码流 | `bytes=2683 fnv_bit=d74bacb1c99a8c30` | 同左 |
| 解码像素 | `dec_frames=5 fnv_px=ab53811322a88564` | 同左 |

逐字节一致（与 G2 的 generic-C 基线值也相同）。

G2 阶段为了 A/B 位精确，AOM 是 `AOM_TARGET_CPU=generic`（所有 SIMD 关闭）。
本轮才真正把目标切到 `riscv` 并开 `ENABLE_RVV`：A 侧编译日志确认
`convolve_rvv.c` / `cdef_block_rvv.c` 等已参与编译。

真机性能：需要带 `--cpu-used` 的 aom 基准（harness 只 5 帧，太短），
上板时用 `aomenc` 跑长序列更合适；本轮未产出 bench 二进制。
